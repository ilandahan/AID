AID - AI Development Methodology for Claude Code

PROJECT OVERVIEW
AID is a comprehensive framework that transforms raw ideas into production-ready software using Claude Code and AI assistance. It systematizes the entire development journey with structured phases, enforced phase gates, a skills system, 39 review sub-agents, and memory-based learning. Ships as a Claude Code plugin.

CORE PURPOSE
Provide a methodical, enforced workflow for building full-stack applications with Claude Code assistance. The methodology stops code being written before the problem is understood, and ensures quality, consistency, and progressive disclosure of work through phase gates.

KEY FEATURES
- Phase Gates (6 phases, 0-5): Discovery -> PRD -> Tech Spec -> Breakdown -> Development -> QA & Ship
- Phase Enforcement: Work is blocked out-of-order by hooks, critical rule enforced
- 39 Registered Sub-Agents: 8 reviewers, 2 builders, 29 phase specialists
- 28 Skills: Automatic skill loading based on role and phase
- 47 Slash Commands: Full workflow management
- 12-Step Dev Pipeline: Automated pipeline with a hard QA gate
- Context Tracking: Real-time tracking of tasks/steps in .aid/context.json
- Memory System: Learning-based improvements through feedback loops
- MCP Integrations: Jira, GitHub, Chrome DevTools, filesystem
- Cucumber/BDD: Gherkin acceptance criteria across 5 languages
- Data Science / ML Track: Full role-data-scientist skill plus phase-specific rule sets
- One-Command Setup: install.sh / install.bat, link-project.sh / .bat for existing projects

PHASE SYSTEM
Phase 0 (Discovery): Research and validation - stakeholder maps, competitive landscape, problem validation
Phase 1 (PRD): Transform raw requirements into PRD document with user stories
Phase 2 (Tech Spec): Create architecture, schemas, API contracts from PRD
Phase 3 (Breakdown): Create Jira epics/stories/tasks from Tech Spec
Phase 4 (Development): Write tests first (TDD), then implement features
Phase 5 (QA & Ship): Testing, code review, deployment preparation

Each phase has entry criteria, required work, exit criteria, and artifacts. A gate blocks progression until the current phase is approved.

KEY SYSTEMS

Phase Gates (phase-enforcement skill + hooks)
- Hooks read .aid/state.json to check current phase
- PreToolUse hook blocks writes and commands that belong to future phases
- Stop hook runs language checks and the QA gate (Phase 4 only)
- Enforces sequential progression

Work Context Tracking (context-tracking skill)
- Maintains .aid/context.json with task/step tracking
- Tracks previous/current/next tasks
- Tracks previous/current/next steps within tasks
- Session logging for continuity

Memory System (learning-based improvements)
- Collects feedback at end of each phase
- Detects patterns in feedback
- Updates skills based on patterns
- Promotes insights to Claude Memory for cross-session learning

SUB-AGENTS (39)
Flat .md files under agents/, one self-contained definition each, prompt inlined.
- 8 reviewers: code, tests, visual QA, phase gates, QA validation, reflection, feedback analysis
- 2 builders: developer, test-engineer
- 29 phase specialists: Phase 0 discovery, Phase 2 architecture, Phase 3 breakdown, Phase 4 sprint work, Phase 5 release, and the PRD pipeline
All invocable by name via subagent_type.

PROJECT STRUCTURE
Components ship at the repository ROOT (Claude Code loads a plugin's components from
the plugin root); install.sh mirrors them into .claude/ as symlinks (macOS/Linux) or
junctions (Windows). The mirrors are gitignored - edit the root copies only.
.claude-plugin/    - plugin.json (name, version, hooks) + marketplace.json
skills/            - 28 skills
agents/            - 39 sub-agents (FLAT - every .md here registers as an agent)
agent-assets/      - Calibration examples + AGENT-STANDARD.md (not scanned as agents)
commands/          - 47 slash commands
rules/             - 23 rule files, incl. the Data Science / ML track
references/        - Shared lookup data (role/phase terminology)
hooks/             - Phase gate, QA gate, pipeline enforcement, session writer
.claude/           - settings.json (project-mode permissions/hooks, copied on link)
docs/              - prd/, tech-spec/, implementation-plan/, research/ outputs + guides
memory-system/     - Learning system (Python package: python -m memory_system)
storybook-preview/ - Component preview workspace
scripts/           - init-project.sh scaffolding
testing/e2e/       - 228 tests covering AID itself
install.sh / install.bat, link-project.sh / .bat
CLAUDE.md          - Main AID instructions Claude loads every session

FILE LOCATIONS
.aid/state.json - Phase tracking
.aid/context.json - Work context
docs/prd/ - Phase 1 outputs (PRD)
docs/tech-spec/ - Phase 2 outputs (technical specification)
docs/implementation-plan/ - Phase 3 outputs (task breakdown)
docs/research/ - Phase 0 outputs (research reports)
.mcp.json - MCP server configuration (from .mcp.json.mac / .windows templates)
CLAUDE.md - Main AID instructions

CRITICAL RULE
Before any work, Claude MUST read .aid/state.json to determine the current phase and
REFUSE work that belongs to a later phase.
